# 使用注意事项

## 前置条件

1. 需要一套 **Shizuku 类特权服务**处于运行状态（Shizuku / Porter / Stellar 均可），并且已给本 App 授权。
2. 游戏包名必须是 `com.unknownworlds.subnautica`，存档在 `files/SavedGames`（老版本为 `files/SNAppData/SavedGames`）。

## 权限框架兼容性（重要）

本 App 使用标准 Shizuku SDK（`dev.rikka.shizuku:api`），声明权限 `moe.shizuku.manager.permission.API_V23` 并注册了 `ShizukuProvider`。不同特权服务的表现如下：

| 服务 | 授权表现 |
| --- | --- |
| 原版 Shizuku / Porter | 首次调用弹授权弹窗，用户手动点“允许”，授权列表里可随时撤销 |
| **Stellar（roro.stellar.manager，Shizuku 魔改版）** | 开启“Shizuku 兼容层”后：**只在第 1 次弹授权确认；之后不再弹，也不会出现在 Stellar「授权应用」列表，无法在 UI 内撤销** |

### 关于 Stellar 的授权行为（免责说明）

这不是本 App 做了什么绕过，而是 Stellar 兼容层自身的行为（Stellar 侧自述：该行为仅在其测试环境验证，未经过大范围测试）。所以会出现：

- App 内状态行显示“已连接 · 已授权（uid 2000）”；
- Stellar 的「授权应用」里却找不到本 App（该列表只登记走 Stellar 自己 `stellar` 权限的应用，不包含 Shizuku 兼容应用）；
- 后续重启 App 不再弹授权框，也无法在 UI 里撤销。

想要“点一下才给、随时能撤”的正规授权，就使用原版 Shizuku（或 Porter）；继续用 Stellar 时，可通过**关掉“Shizuku 兼容层”或停止服务**立即收回权限。

> 同理，任何其它走 Shizuku SDK 的应用在 Stellar 兼容层下也是同一套行为，这是框架层面的问题，与本 App 无关。
> 建议把此条同步反馈给 Stellar 作者（仓库：https://github.com/roro2239/Stellar）。

## 位置为什么不动

App 读的是**存档文件**，不是游戏内存。所以：

- 进游戏 → 设置里**手动保存**一次 → 回 App 点「更新地图」，位置才会更新。
- 游戏内自动存档（打开 PDA 触发，设置里可设为 2.5 分钟）也会刷新存档。
- 在游戏里走动但没存档，App 里是看不到变化的。

## 朝向三角

- 存档没有朝向数据，三角需要手动指定：**长按地图上你想朝向的点**，三角就会转过去，角度会记在本地。
- 双击地图可回到玩家位置。

## 底图

- 仓库不带地图。请把正方形、覆盖 -2000~2000 的底图放到 `/storage/emulated/0/DeepSeaNav/map.png`，或编进 `assets/subnautica_map.png`。
- 若底图自带上、左、右、下边距，标记会整体偏移，需要按实际边距调整 `MainActivity` 里的映射公式。

## 权限与安全

- 把 shell 身份借给 App 等于给了它读其它应用私有目录的能力，请只装可信来源的 APK。
- 本 App 只做 `ls / cat / stat` 读文件，不写游戏存档，不改游戏数据。

## 已知坑

- `adb` 命令在手机本地终端里是没有的（`sh: adb: inaccessible or not found`）：`adb` 是电脑端程序，手机里要用 Su/Shizuku 类服务拿 shell 身份，别再套 `adb shell` 外壳。
- Android 11+ 用无线调试启动特权服务时，重启后需要重新配对启动一次（Root 启动可开机自启）。
- debug 签名安装即可；换签名版本覆盖安装需先卸载，且覆盖安装后旧授权会失效，需要重新授权一次。
- Android 13+ 的 vivo/OPPO 等机型可能限制后台启动：把本应用和特权服务都加入后台白名单。
