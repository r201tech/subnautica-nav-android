# 存档格式：scene-objects.bin 逐字节解析

以下是实测样本（Android 版存档 `slotc9241003`）的分析结果，供二次开发和适配参考。

## 1. 文件位置

```
/sdcard/Android/data/com.unknownworlds.subnautica/files/SavedGames/
├─ options/                     # 画质等设置
└─ slotc9241003/                # 一个存档槽
   ├─ gameinfo.json             # 明文元数据（无坐标）
   ├─ global-objects.bin        # 全局对象
   ├─ scene-objects.bin         # ★ 玩家坐标在这里
   ├─ CellsCache/*.zip          # 地形缓存
   └─ screenshot.jpg / screenshots/
```

> 老版本路径多一层 `SNAppData`，App 里两套都试。

## 2. 整体结构

整个文件是**一个 varint 长度前缀 + 一串 protobuf `f2` 记录**：

```
<varint 长度> 0x12 <varint> body ... 0x12 <varint> body ...
```

- 每条记录：`f1 = 对象名（string）`，`f2 = 对象体`，体内 `f3 = 组件列表`。
- 组件条目形如：`0a <varint> 06 "Oxygen" 10 01` + 一块数据。

## 3. Transform 的数据块

组件名是 `UnityEngine.Transform`，定位锚点（27 字节）：

```
0a 15  "UnityEngine.Transform"  10 01
```

紧随其后（可选一个 `38 <varint>` 字段）就是位置块：

```
0f                      # 长度 15
  0d <4 字节 float>     # x
  15 <4 字节 float>     # y
  1d <4 字节 float>     # z
12 14                   # 长度 20 = 旋转四元数
  0d <f> 15 <f> 1d <f> 25 <f>   # (x,y,z,w)
```

注意：**tag 字节占位**，读 float 时要跳过 `0d/15/1d/25` 各 1 字节。

## 4. 取玩家坐标

1. 外层扫描 `f2` 记录，看记录开头是不是 `0a 06 "Player"`；
2. 在该记录内部找**第一个** `UnityEngine.Transform` 锚点；
3. 按上面的格式读 3 个 float，即为**世界坐标**（根对象，localPosition 等于世界坐标）。

实测样本（存档时玩家正站在 5 号救生舱旁）：

```
Player     x = -51.62   y = 1.85   z = -118.11
EscapePod  x = -51.51   y = -0.05  z = -119.17
```

## 5. 关于朝向（重要）

`Player` 的旋转四元数是 `(0, 0, 0, 1)`（单位四元数），子对象（Head / 装备等）也都是单位四元数 —— **游戏没有把玩家朝向写进存档**，读档后朝向会被重置。所以想显示朝向只能靠玩家手动指定，不要指望从存档里算。

（其他物体如救生舱、极光号残骸的四元数是有效值，可以按需解析。）

## 6. 坐标 → 像素

地图坐标轴：`X` 为东西（西 -2000，东 +2000），`Z` 为南北（北 +2000，南 -2000），`Y` 向上、海平面约为 0。

```
px = (x + 2000) / 4000 * width
py = (2000 - z) / 4000 * height
```

## 7. 局限

- 只拿到**存档那一刻**的位置；想刷新就得在游戏里手动存一次（自动存档：打开 PDA 触发，可设 2.5 分钟）。
- 存档是 IL2CPP 构建的游戏写的，字段名与顺序可能随版本变化；结构不对时 App 会提示“解析失败”，需要重新采样分析。
